# WokBee 产品技术方案（产品经理可读版）

> 版本：v0.1.0  
> 读者：产品经理 / 业务同学（不要求会写代码）  
> 目标：讲清「产品是什么、怎么用、技术怎么搭、边界在哪」，方便评审需求与排期。

---

## 1. 一句话定位

**WokBee** 是一款装在 Windows 电脑上的 AI 桌面助手：既能像 ChatGPT 一样多会话聊天（**TokBee**），也能按「项目」让 Agent 在本地目录里干活并沉淀经验（**WokBee**）。

模型来自你自己配置的 **OpenAI 兼容 API**（官方、中转、私有化都行），数据默认落在本机，不强制上云。

---

## 2. 解决什么问题

| 痛点 | 产品怎么对 |
|------|------------|
| 聊天工具和「能改文件、能跑流程」的 Agent 割裂 | 同一桌面应用里两块能力共用一套厂商/模型配置 |
| 项目型工作没有「工作区 + 交付物 + 历史」 | WokBee 以项目为单位管目录、状态、事件流 |
| 重复劳动每次都靠模型重想 | 成功路径可总结成「经验」和本地脚本，下次优先复用 |
| 高风险操作（写文件、执行命令）不敢全自动 | 可按风险等级配置「免审 / 需人工审批」 |
| 能力扩展靠改代码 | Skills（技能包）+ MCP（外挂工具协议）可配置扩展 |

## 3. 产品信息架构（你在界面上看到的）

```
WokBee 应用
├── TokBee（对话）
├── WokBee（项目 Agent）
├── AI配置
│   ├── AI 角色
│   ├── 厂商设置          ← 模型/Key/默认模型（全局）
│   ├── TokBee 设置       ← 新建对话的默认参数
│   ├── WokBee 设置       ← 工作区、审核策略、步数等
│   ├── Skills
│   └── MCP
└── 设置（主题等通用项）
```

### 3.1 品牌怎么理解（容易混）

| 名字 | 含义 |
|------|------|
| **WokBee** | 整个应用的产品名（窗口标题也是它） |
| **TokBee** | 应用里的「聊天」模块品牌 |
| **WokBee（导航项）** | 应用里的「项目 Agent」模块品牌 |

一句话：**产品叫 WokBee；聊天叫 TokBee；项目干活也叫 WokBee。**

## 4. 核心用户路径

### 4.1 第一次用（配置）

1. 打开 **AI配置 → 厂商设置**  
2. 添加厂商（内置如 DeepSeek，或自定义 OpenAI 兼容 Host）  
3. 填 API Key、Host，拉取或添加模型，勾选启用  
4. 在要用的模型旁点 **「默认」**  
5. （可选）配 AI 角色、TokBee/WokBee 默认参数、Skills、MCP  

**默认模型规则（产品语义）：**

- 用户在「厂商设置」点的 **默认徽章** = 全局主默认  
- **新建对话 / 新建项目** 优先继承这个默认  
- 「WokBee 设置」里的默认模型是**可选回退**（未设厂商默认时才用）

### 4.2 TokBee：日常对话

1. 左侧进 **TokBee** → 新建对话  
2. 选模型、选角色、发消息  
3. 上下文快满时可压缩摘要（界面有用量环）  
4. 单会话参数可临时改；全局默认去 **TokBee 设置**

### 4.3 WokBee：项目工作流

1. 左侧进 **WokBee** → 新建项目（名称/目标可空；空名称会用「项目+时间」）  
2. 项目会绑定当前**全局默认模型**，并继承全局**审核策略**（之后可单独改）  
3. 底部两个主按钮（能力不同）：  
   - **发送**：完整 Agent 能力对话（可工具调用），不跑「经验管线」那套项目推进闭环  
   - **运行**：按目标推进项目（经验 → 脚本优先 → Agent → 可总结经验）  
4. 需要审批的操作会停住等人确认  
5. 交付物、上传文件、归档、脚本等落在项目目录里

## 5. 能力地图（按模块）

### 5.1 TokBee（聊天）

| 能力 | 说明 |
|------|------|
| 多会话 | 会话列表、新建/切换；参数可按会话存 |
| OpenAI 兼容调用 | 走你配置的 Host + Key |
| AI 角色 | 从角色库套系统提示词 |
| 上下文预算 | 按模型上下文窗口估算用量；支持压缩 |
| 附件/文档 | 支持常见文档解析后参与对话（PDF/Office 等） |

### 5.2 WokBee（项目 Agent）

| 能力 | 说明 |
|------|------|
| 项目管理 | 列表、搜索、状态（空闲/运行中/待审批/失败/完成） |
| 目标与标题 | Agent 可更新目标/标题；标题有长度上限（展示友好） |
| 工具执行 | 读写下本地项目目录、联网工具、本地脚本执行等 |
| 审核策略 | 读 / 写 / 常规 / 高危 四级；勾选=该级免审 |
| 经验沉淀 | 成功路径可总结为经验文件；下次运行优先参考最新一份 |
| 脚本固化 | 可复用步骤落到 `scripts/`（不随归档清空） |
| 归档 | 会话快照进 `archives/`；Agent 被要求不要拿归档当本轮数据源 |
| Skills | 全局技能目录只读挂载到 Agent，不复制进每个项目 |
| MCP | 把配置好的 MCP Server 工具挂进 Agent |

### 5.3 AI配置（共用底座）

厂商、角色、Skills、MCP 是 **TokBee 与 WokBee 共用的能力底座**，避免两套 Key、两套模型列表。

## 6. 技术架构（够评审用的那一层）

不必记类名，记住分层即可：

```
┌─────────────────────────────────────────┐
│  界面层（PySide6）                        │
│  TokBee 聊天页 / WokBee 项目页 / AI配置   │
├─────────────────────────────────────────┤
│  应用壳（tokbee 包）                      │
│  启动、主题、主窗口、厂商/角色/对话配置    │
├─────────────────────────────────────────┤
│  项目 Agent（wokbee 包）                  │
│  项目存储、运行器、审批、经验、Skills/MCP │
├─────────────────────────────────────────┤
│  外部能力                                 │
│  OpenAI 兼容 API · Deep Agents/LangGraph  │
│  MCP Servers · 本机文件系统               │
└─────────────────────────────────────────┘
```

### 6.1 代码分包（给产研对齐用）

| 包 | 职责 |
|----|------|
| `src/tokbee/` | 应用入口、主窗口、TokBee 对话、厂商/角色/会话默认、通用配置 |
| `src/wokbee/` | 项目模型与磁盘布局、Agent 运行、审批、经验、Skills/MCP UI 与存储 |

启动入口：`main.py` → `tokbee.app.Application`。

### 6.2 WokBee 运行时（简化时序）

**运行（Run）大致顺序：**

1. 解析项目绑定的模型（无绑定则用厂商默认）  
2. 准备项目目录与 memory 约定  
3. 加载最新经验（若有）、挂载 Skills、连接 MCP 工具  
4. 组装 Agent（Deep Agents）并开跑  
5. 若命中需审批的工具 → 暂停 → 用户批准/拒绝 → 继续  
6. 结束后可后台总结经验（避免卡死界面）  

**发送（Send）**：同样可用完整工具能力，但**不走**「经验管线推进目标」那套 Run 逻辑。

### 6.3 项目目录约定（产品要懂「文件落哪」）

每个项目在工作区下有独立文件夹，常见子目录：

| 目录 | 用途（产品语言） |
|------|------------------|
| `memory/` | 记忆与经验（含 experiences） |
| `workspace/` | Agent 工作沙箱；脚本运行输出落盘为 `script_callback_<脚本名>.md` |
| `deliverables/` | 交付物（最终成果） |
| `uploads/` | 用户上传、给 Agent 读 |
| `runs/` | 运行日志/事件流 |
| `scripts/` | 总结阶段固化/AI 手写的可复用脚本与 `pipeline.json`（`steps` 为有序执行清单，可连续脚本或连续 AI） |
| `archives/` | 归档快照（本轮运行不应当数据源） |

## 7. 数据与隐私

| 类型 | 默认位置 | 说明 |
|------|----------|------|
| 应用配置/厂商/角色等 | `~/.wokbee/` | 本机用户目录 |
| Skills | `~/.wokbee/skills/` | 可改路径 |
| 项目文件 | `~/WokBeeWorkspace/<项目>/` | 可在 WokBee 设置改根目录 |
| 模型调用 | 你配置的 API Host | Key 存在本机配置；流量走该 Host |

**产品表述建议：** 本地优先存储；模型推理发生在你指定的 API 服务商侧。

兼容：若存在旧目录 `~/.tokbee/`，会尝试迁移到 `~/.wokbee/`。

## 8. 安全与可控（评审必问）

| 机制 | 产品含义 |
|------|----------|
| 审核策略 | 按风险等级决定「直接执行」还是「先问人」 |
| 项目隔离 | Agent 主要在当前项目目录内工作 |
| 归档隔离 | 约定不把 `archives/` 当本轮输入 |
| Skills 只读挂载 | 技能包共享但不复制污染项目 |
| 取消/暂停 | 运行中可中断；待审批可拒绝 |

高危能力（写盘、执行命令、联网）默认应偏谨慎；全局默认策略可在 **WokBee 设置**改，单个项目可覆盖。

## 9. 关键设计决策（方便你拍板/追问）

1. **一套厂商配置，两块业务复用**  
   避免「聊天一个 Key、Agent 另一个 Key」的认知负担。

2. **发送 ≠ 运行**  
   发送：强能力对话；运行：冲项目目标 + 经验/脚本闭环。  
   UI 上要持续讲清差异，否则用户会以为两个按钮一样。

3. **默认模型以「厂商设置」为准**  
   用户最常在模型旁点「默认」；新建项目/对话应对齐这个心智。

4. **经验只加载最新一份**  
   降低上下文噪音；旧经验仍在磁盘，但不默认全塞给模型。

5. **Skills / MCP 全局配置**  
   扩展点放在 AI配置，不要求每个项目重复装技能。

## 10. 非目标 / 当前边界（v0.1）

避免评审时期望过高：

- 不做多人协作云端工作区（本机应用）  
- 不做「任意网站一键登录代操作」类 RPA 全家桶（能力取决于工具与 MCP）  
- 不内置模型本身，依赖外部 OpenAI 兼容 API  
- 当前主目标平台是 **Windows**  
- Agent 能力强度受模型质量、审核策略、Skills/MCP 配置影响，不是固定成功率产品

## 11. 版本与迭代建议（产品视角）

**已具备（v0.1 基线）：**

- TokBee 多会话 + 上下文用量  
- WokBee 项目 Agent + 审批 + 经验/脚本思路  
- 厂商/角色/Skills/MCP 配置台  
- 本机数据目录与项目工作区  

**后续可排期方向（示例，非承诺）：**

| 方向 | 价值 |
|------|------|
| 项目模板 / 示例项目 | 降低首次成功路径成本 |
| 运行回放与失败归因更可读 | 提升「可解释、可复盘」 |
| Skills 商店或一键导入 | 降低扩展成本 |
| 更细的权限与路径白名单 | 企业场景安全感 |
| 安装包 / 自动更新 | 非技术用户分发 |

## 12. 产研协作时怎么提需求（模板）

提需求时尽量写清这五条，研发返工会少很多：

1. **落在哪块**：TokBee / WokBee / AI配置 / 设置  
2. **用户故事**：谁、在什么场景、想完成什么  
3. **成功标准**：界面上看到什么、磁盘上多了什么、失败时怎么提示  
4. **默认与权限**：是否改全局默认、是否要审批、是否动本机文件  
5. **非目标**：这次明确不做的（避免范围膨胀）

## 13. 附录：名词表

| 名词 | 解释 |
|------|------|
| OpenAI 兼容 API | 接口形态类似 OpenAI Chat Completions，Host 可换 |

| Skills | 带 `SKILL.md` 的技能文件夹，给 Agent 按需用 |
| MCP | Model Context Protocol，外挂工具/数据源的协议 |
| 经验（Lesson） | 对成功路径的结构化总结，供下次运行参考 |
| 工作区 | WokBee 项目文件根目录 |
